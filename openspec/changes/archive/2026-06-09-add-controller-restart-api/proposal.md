## Why

Во время отладки и удалённой эксплуатации нужен штатный способ перезагрузить контроллер через HTTP API без физического доступа. Сейчас отдельного restart endpoint нет, из-за чего операторы вынуждены использовать кнопку reset или косвенные OTA-пути.

## What Changes

- Добавить API endpoint для контролируемой перезагрузки контроллера через HTTP.
- Определить поведение endpoint: валидация запроса, попытка принудительного `flushNow()` реестра устройств, формирование ответа и только затем restart.
- Возвращать явные коды ошибок, если безопасная перезагрузка невозможна (например, ошибка flush реестра).
- Зафиксировать минимальные ограничения по доступу к endpoint для dev-билдов, чтобы endpoint не оказался незащищённым в обычной эксплуатации.

## Capabilities

### New Capabilities
- `controller-runtime-control`: Управление runtime-действиями контроллера через API, включая безопасную перезагрузку с предварительным flush и детерминированным HTTP-ответом.

### Modified Capabilities
- `device-registry`: Уточнить контракт forced flush перед контролируемой перезагрузкой, инициированной новым runtime-control API.

## Impact

- Затрагивает HTTP portal routes и обработчики системных endpoint.
- Использует существующий `DeviceRegistry::flushNow()` перед перезагрузкой.
- Потребуются тесты route/handler-логики для успешного restart path и для fail path при ошибке flush.
