Die bereitstellbaren Binaries (`bootloader.bin`, `partitions.bin`,
`firmware.bin`, `littlefs.bin`) werden aus jedem Commit erzeugt und enthalten
sowohl die Firmware als auch die Webportal-Assets.

## Firmware-Variante waehlen

| Variante | WiFi-Einrichtung ueber BLE | GPIO 32 | Setup-Access-Point und Webportal |
| --- | --- | --- | --- |
| **Standard** | Enthalten | Fuer den BLE-Aktivierungstaster reserviert | Verfuegbar |
| **Without BLE** | BLE-Code wird nicht kompiliert | Fuer ein anderes Geraet verfuegbar | Verfuegbar |

Waehle **Standard** nur, wenn du WiFi ueber eine mobile BLE-App einrichten
moechtest. Waehle **Without BLE**, wenn Access Point und Webportal genuegen:
Diese Firmware ist kleiner und reserviert GPIO 32 nicht.

## Option 1 - Webinstaller (am einfachsten)

Direkt im Browser flashen, ohne zusaetzliche Software:

<LinkButton href="/gekko/install/" icon="rocket">Gekko-Webinstaller oeffnen</LinkButton>

<Steps>

1. Verbinde das ESP32-Board mit einem USB-**Daten**kabel mit dem Computer.

2. Oeffne den Installer in **Chrome**, **Edge** oder **Opera** auf dem Desktop
   (Web Serial ist in Firefox/Safari und auf Mobilgeraeten nicht verfuegbar).

3. Waehle **Standard** oder **Without BLE**, klicke auf die zugehoerige
   Schaltflaeche, waehle den seriellen Port und bestaetige.

4. Warte, bis der Fortschrittsbalken fertig ist, und fahre dann mit
   [First boot & WiFi setup](/gekko/de/getting-started/first-boot-wifi/) fort.

</Steps>

:::caution
Browser-Flashen haengt von OS-/USB-Chip-Seriell-Unterstuetzung ab und hat auf
manchen Linux-+USB-Seriell-Kombinationen bekannte Probleme. Wenn es nicht
funktioniert, nimm eine der Optionen unten - sie flashen exakt dieselben
Binaries.
:::

## Option 2 - esptool

<Tabs syncKey="os">
  <TabItem label="Windows / macOS / Linux (ohne Python)">

    1. Lade das standalone `esptool`-Binary fuer dein Betriebssystem von der
       [esptool releases page](https://github.com/espressif/esptool/releases).
    2. Lege es neben die Skripte im `webflash/`-Ordner des Repositories
       (unter macOS/Linux in `esptool` umbenennen, unter Windows in
       `esptool.exe`).
    3. Starte `webflash/flash.sh [PORT]` (macOS/Linux) oder
       `webflash/flash.bat [PORT]` (Windows). Ohne Port-Argument erkennt
       esptool den Port automatisch.
       Fuer das no-BLE-CI-Paket nutze `flash.sh no-ble [PORT]` oder
       `flash.bat no-ble [PORT]`.

  </TabItem>
  <TabItem label="Python">

    ```sh
    pip install esptool
    python3 webflash/flash.py [standard|no-ble] [PORT]
    ```

  </TabItem>
</Tabs>

## Option 3 - PlatformIO (fuer die Entwicklung)

Wenn du aus dem Quellcode baust:

```sh
# Standard
pio run -e esp32dev -t upload
pio run -e esp32dev -t uploadfs

# Without BLE
pio run -e esp32dev_no_ble -t upload
pio run -e esp32dev_no_ble -t uploadfs
```

Siehe `CLAUDE.md` und `docs/platformio-environments.md` im Repository fuer
den kompletten Entwicklungsworkflow.
