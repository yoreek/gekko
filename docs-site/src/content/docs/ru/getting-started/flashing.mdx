Готовые к прошивке бинарники (`bootloader.bin`, `partitions.bin`,
`firmware.bin`, `littlefs.bin`) собираются для каждого коммита и для каждого
поддерживаемого чипа (классическая ESP32, ESP32-S2, ESP32-S3, ESP32-C3,
ESP32-C6), и содержат прошивку и ресурсы веб-портала.

## Выбор варианта прошивки

| Вариант | Настройка WiFi через BLE | GPIO 32 | Точка доступа и веб-портал | Чипы |
| --- | --- | --- | --- | --- |
| **Рекомендуемый** | Код BLE не компилируется в прошивку | Доступен для другого устройства | Доступны | ESP32, S2, S3, C3, C6 |
| **С BLE** | Включена | Зарезервирован для кнопки активации BLE | Доступны | только ESP32, S3, C3 |

Выбирайте **Рекомендуемый** вариант, если не нужна настройка WiFi из
мобильного BLE-приложения: эта прошивка меньше и не резервирует GPIO 32.
Выбирайте **С BLE**, только если нужна настройка через мобильное
BLE-приложение; для ESP32-S2 такого варианта нет (в чипе вообще отсутствует
радиомодуль BLE), как и для ESP32-C6 (конфликт линковщика во фреймворке
`pioarduino`/Arduino-ESP32 core 3.x) — подробности в `docs/esp32-board-models.md`
в репозитории.

## Вариант 1 — веб-установщик (проще всего)

Прошивка прямо из браузера, без установки дополнительного ПО:

<LinkButton href="/gekko/install/" icon="rocket">Открыть веб-установщик Gekko</LinkButton>

<Steps>

1. Подключите плату к компьютеру USB-кабелем **для передачи данных**.

2. Откройте установщик в **Chrome**, **Edge** или **Opera** на рабочем столе
   (Web Serial недоступен в Firefox/Safari и на мобильных браузерах).

3. Выберите **Рекомендуемый** или **С BLE**, нажмите соответствующую кнопку
   установки, выберите serial port платы в диалоге браузера и подтвердите.
   Установщик сам определяет подключённый чип — выбирать его вручную не
   нужно. При первой установке предлагается стереть устройство.

4. Дождитесь завершения прогресс-бара, затем перейдите к
   [Первому запуску и WiFi-setup](/gekko/ru/getting-started/first-boot-wifi/).

</Steps>

:::caution
Прошивка через браузер зависит от поддержки serial со стороны ОС и USB-чипа,
и на некоторых сочетаниях Linux + USB-serial chip есть известные проблемы. Если
не получилось, используйте один из вариантов ниже — они прошивают ровно те же
бинарники.
:::

## Вариант 2 — esptool

<Tabs syncKey="os">
  <TabItem label="Windows / macOS / Linux (без Python)">

    1. Скачайте standalone-бинарник `esptool` для своей ОС со
       [esptool releases page](https://github.com/espressif/esptool/releases).
    2. Положите его рядом со скриптами в папке репозитория `webflash/`
       (переименуйте в `esptool` на macOS/Linux, в `esptool.exe` на Windows).
    3. Запустите скрипт прошивки, подставив `CHIP` под вашу плату (`esp32`
       по умолчанию, `esp32s2`, `esp32s3`, `esp32c3`, `esp32c6`). Если порт не
       указан, esptool попытается найти его сам.

       ```sh
       webflash/flash.sh [default|ble] [CHIP] [PORT]   # macOS/Linux
       webflash/flash.bat [default|ble] [CHIP] [PORT]  # Windows
       ```

       Пример — BLE-сборка для платы ESP32-C3:

       ```sh
       webflash/flash.sh ble esp32c3
       ```

  </TabItem>
  <TabItem label="Python">

    ```sh
    pip install esptool
    python3 webflash/flash.py [default|ble] [CHIP] [PORT]
    ```

  </TabItem>
</Tabs>

## Вариант 3 — PlatformIO (для разработки)

Если вы собираете из исходников:

```sh
# Рекомендуемый (без BLE)
pio run -e esp32dev -t upload
pio run -e esp32dev -t uploadfs

# С BLE
pio run -e esp32dev_ble -t upload
pio run -e esp32dev_ble -t uploadfs

# Другие чипы: esp32s3[_ble], esp32c3[_ble], esp32s2, esp32c6
pio run -e esp32s3_ble -t upload
```

Смотрите `CLAUDE.md` и `docs/platformio-environments.md` в репозитории для
полного рабочего процесса разработки.
