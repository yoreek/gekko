Два типа устройств работают вместе, чтобы автоматизировать переключения:
**schedule** хранит правила по времени суток и сообщает, активно ли оно
сейчас, а **auto switch** управляет реальным выключателем по логическому AND
подключённых условий.

## Расписание

Устройство [schedule](/gekko/ru/reference/devices/schedule/) хранит до 4 правил.
У каждого правила есть:

- **weekday mask** — какие дни недели оно покрывает;
- **time window** — start и end minute дня (точность до минуты, без секунд);
- **mode**:
  - **Always on** — активно всё окно;
  - **Interval** — делит окно на равные части и активно первые N минут каждой
    части (для периодической циркуляции, туманообразования и т. п.).

Расписание активно, когда совпадает **любое** включённое правило. Редактор
правил в портале показывает client-side preview on/off, вычисленный по вашим
правилам и часам браузера — это помечено как estimate, потому что сам
устройство оценивает правила по своим часам и timezone.

:::note[Дайте устройству надёжные часы]
Расписание откажется работать, пока часы устройства не выглядят правдоподобно.
Используйте NTP (задайте timezone на странице **Time**) или добавьте RTC
DS3231, чтобы расписания переживали и пропадание интернета, и перезагрузки.
:::

## Auto switch

Auto switch оборачивает реальный switch (GPIO или port-expander) и управляет
им по up to **6 condition dependencies** — schedules, других switches или
других auto switches — каждая из которых может быть **inverted**. Все
условия объединяются через AND: выход включён только пока выполняется каждое
условие. Без подключённых условий auto switch в режиме Auto остаётся
выключенным.

Его режимы:

- **Off / On** — ручной override; условия игнорируются. Переключение с
  дашборда задаёт именно это.
- **Auto** — следовать условиям.
- **Paused** — временно выключено на заданную длительность, затем
  автоматически возвращается в **Auto**. Pause доступен только из режима Auto.
  Перезагрузка посреди паузы возобновляет её с правильным оставшимся временем.

При переходе в Auto (или Paused) целевой switch всегда сначала принудительно
выключается, а затем передаётся условиям — так прежнее ручное "On" никогда
тихо не остаётся висеть.

Поскольку сам auto switch действует и как switch, и как condition, можно
строить цепочки автоматики: auto switch "feeding mode" может одновременно
гейтить несколько других auto switch через их inverted condition slots.

## Пример: аквариумный свет с кнопкой паузы

1. Создайте **Schedule** "Light hours": каждый день, 09:00–21:00, always on.
2. Создайте **GPIO Switch** "Light relay" на пине, который управляет светом.
3. Создайте **Auto Switch** "Light": target = "Light relay", condition =
   "Light hours", mode = Auto.
4. Закрепите "Light" на дашборде. Теперь он следует расписанию; нажмите его
   для ручного override, используйте **pause** во время обслуживания и
   верните в Auto, когда закончите.

## Связанные устройства

- **[Thermostat](/gekko/ru/reference/devices/thermostat/)** — управление
  температурой с гистерезисом и выходом на switch.
- **[Dosing pump](/gekko/ru/reference/devices/dosing-pump/)** — дозирование по
  расписанию с калибровкой, учётом контейнера и журналом доз.
- **[Scheduled analog output](/gekko/ru/reference/devices/analog-outputs/)** —
  суточная кривая яркости/уровня для PWM-выходов, которую можно собирать в
  многоканальные светильники.
