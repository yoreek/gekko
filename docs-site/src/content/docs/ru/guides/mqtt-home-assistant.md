Gekko поддерживает **Home Assistant MQTT discovery**: подключите его к вашему
MQTT-брокеру один раз, а затем публикуйте любое устройство одним
переключателем — и оно само появится в Home Assistant с правильным типом
сущности, именем и иконкой. Никакого YAML, никакой ручной настройки сущностей.

## Что вы получаете

![Устройства Gekko, появляющиеся в Home Assistant как switch, sensors и climate entities](../../../../assets/diagrams/ha-entities.svg)

Каждое опубликованное устройство Gekko становится нативной сущностью HA, а
управление работает в обе стороны в реальном времени:

| Устройство Gekko | В Home Assistant | Можно |
| --- | --- | --- |
| GPIO / port-expander / auto switch | `switch` | переключать с любой панели HA, использовать в автоматизациях |
| Аналоговый выход (fade / scheduled) | `light` (яркость) | диммировать из HA, добавлять в сценарии |
| Pixel strip | `light` (яркость) | управлять питанием и яркостью адресной ленты |
| Pixel effect solid | `light` (RGB) | выбирать цвет ленты на цветовом круге HA |
| Pixel effect alert | `binary_sensor` | видеть в HA, мигает ли сейчас аварийный индикатор |
| DS18B20, NTC thermistor | `sensor` | строить график истории, запускать автоматизации по температуре |
| HTU21 | два `sensor` (temperature + humidity) | то же самое, независимо |
| Binary sensor | `binary_sensor` | уведомления о протечке/двери через HA |
| Thermostat | `climate` | менять режим и уставку с карточки термостата HA |

Так что ваш аквариумный свет может участвовать в сценах HA, датчик протечки
может присылать уведомление на телефон, а термостат будет рядом с климатом
дома — при этом всё продолжает работать локально на ESP32, даже если HA
недоступен.

## Настройка

1. **Подключите брокер один раз.** На странице портала **MQTT / Home Assistant**
   введите адрес брокера, порт и учётные данные (TLS поддерживается) и
   включите **Enable MQTT**. Изменения применяются через аккуратное
   переподключение — без перезагрузки. MQTT подключается только когда
   устройство уже в вашей WiFi-сети в режиме station, никогда не в режиме
   setup-AP.

   ![Страница настроек MQTT broker](../../../../assets/screenshots/portal-mqtt.png)

2. **Убедитесь, что HA смотрит на тот же брокер** и что у MQTT integration
   включён discovery (по умолчанию так и есть).

3. **Публикуйте устройства.** На странице каждого поддерживаемого устройства
   есть карточка **Home Assistant** — включите **Publish to Home Assistant**,
   при желании задайте HA-специфичное имя и сохраните:

   ![Карточка Home Assistant у устройства с переключателем публикации](../../../../assets/screenshots/device-ha-card.png)

   Через несколько секунд устройство появится в HA в разделе **Settings →
   Devices & services → MQTT**, сгруппированное под вашим контроллером Gekko.
   Отмена публикации убирает его так же аккуратно.

## Вариант на этапе сборки

Поддержка MQTT компилируется в прошивку по требованию (`-DWITH_HOME_ASSISTANT`
в `platformio.ini`) — прошивка без неё вообще не содержит MQTT-кода, что важно
для плат на 4 МБ. Портал явно показывает разницу:

- бейдж **Available / Not available** на странице MQTT показывает, есть ли
  эта функция в данной *сборке*;
- переключатель **Enable MQTT** говорит прошивке, подключаться ли сейчас на
  самом деле.

На сборках без этой функции страница MQTT показывает пояснение, а карточки HA
для устройств не отображаются.

Полную архитектуру (схему топиков, адаптеры, TLS-сертификаты) см. в
[`docs/mqtt-home-assistant.md`](https://github.com/yoreek/gekko/blob/master/docs/mqtt-home-assistant.md)
в репозитории.
