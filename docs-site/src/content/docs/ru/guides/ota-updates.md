В Gekko есть два over-the-air пути, и оба **выключены в стандартной сборке**
— обычной ESP32-плате на 4 МБ просто не хватает flash headroom для OTA
partition scheme рядом с прошивкой, веб-порталом и конфигурацией.

## Стандартная сборка: обновление через serial

В стандартной single-app раскладке обновления выполняются как [reflash over USB](/gekko/ru/getting-started/flashing/).
Конфигурация устройства хранится в NVS и переживает перепрошивку — но перед
обновлением всё равно стоит держать под рукой
[backup bundle](/gekko/ru/guides/backup-restore/).

## PlatformIO OTA upload (для разработчиков)

Для плат с достаточным флешем и OTA-enabled partition layout окружение
`esp32dev_ota` в PlatformIO доставляет ту же самую прошивку по сети, а не по
serial:

```sh
pio run -e esp32dev_ota -t upload
```

Это специально alias транспорта загрузки для `esp32dev` — тот же образ, те
же build flags — так что serial и OTA deliveries остаются byte-identical.

## Web OTA (portal upload)

Прошивка, собранная с guarded Web OTA option, добавляет в портал страницу
**OTA**: вы загружаете образ прошивки из браузера, а устройство проверяет его,
завершает установку и перезагружается в него. Слишком большие или оборванные
загрузки не затрагивают запущенную прошивку. На сборках без этой функции
портал просто скрывает страницу OTA.

:::note
Считайте Web OTA инструментом для разработки/продвинутого использования:
включайте его только на платах с запасом флеша, согласно
`docs/platformio-environments.md` в репозитории.
:::
