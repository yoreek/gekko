Вся конфигурация устройства — каждое устройство, его настройки, граф
зависимостей, раскладки дисплеев и дашборд — экспортируется как **один файл**,
который можно скачать, сохранить, отредактировать вручную и восстановить на
том же или другом контроллере.

## Через портал

Откройте **System → Backup**:

- **Download** сохраняет `device-setup.ndjson`.
- **Restore** загружает bundle с подтверждением. Сначала bundle
  валидируется; любая ошибка отклоняет импорт **без изменения живой
  конфигурации**, а успешное восстановление атомарно заменяет все устройства.

## Через командную строку

```sh
# backup
curl -fsS http://<device-ip>/api/device-setup/export -o device-setup.ndjson

# restore
curl -fsS -F "bundle=@device-setup.ndjson" http://<device-ip>/api/device-setup/import
```

## Bundle — это обычный JSON, который можно править вручную

Файл имеет формат NDJSON: один JSON-объект на строку, в той же структуре,
которую принимает REST API. Вы можете поправить номер пина в текстовом
редакторе или даже собрать минимальный bundle с нуля:

```json
{"kind":"transfer_envelope","transferSchemaVersion":3}
{"kind":"device","record":{"id":4,"typeName":"gpio_switch"},"config":{"name":"Pump","enabled":true,"gpioPin":26}}
```

Для каждого устройства обязательны только `record.id` и `record.typeName` —
всё остальное получает значения по умолчанию. Идентификаторы зависимостей
ссылаются на другие `record.id` в том же bundle, а bundle из старой прошивки
импортируется без проблем, если его поля всё ещё корректно парсятся. Полное
описание формата: [`docs/backup-and-restore.md`](https://github.com/yoreek/gekko/blob/master/docs/backup-and-restore.md).

## Что входит и не входит

**Входит:** реестр устройств (все типы, зависимости, раскладки дисплеев) и
раскладка дашборда.

**Не входит:** WiFi-учётные данные, настройки MQTT, сохранённое runtime-состояние
и состояние прошивки/OTA.

## Автоматические резервные копии

У прошивки намеренно нет встроенного планировщика — endpoint экспорта это
обычный GET, который может забирать любой узел в вашей LAN. Пример ежедневного
cron:

```sh
# /etc/cron.d/gekko-backup — ежедневно в 03:00, хранить 30 дней
0 3 * * * user curl -fsS http://192.168.1.240/api/device-setup/export \
  -o /var/backups/gekko/device-setup-$(date +\%F).ndjson \
  && find /var/backups/gekko -name 'device-setup-*.ndjson' -mtime +30 -delete
```

Или automation в Home Assistant с `shell_command` и триггером по времени.
Смотрите doc из репозитория выше для готового фрагмента под HA.

:::caution
В портале нет аутентификации — любой в вашей сети может прочитать bundle
(и сам портал). Конфигурации не содержат WiFi/MQTT-секретов, но держите
контроллер в доверенной сети.
:::
