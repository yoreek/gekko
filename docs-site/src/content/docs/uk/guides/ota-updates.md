У Gekko є два OTA-шляхи, і обидва **вимкнені в стандартній збірці** — на
звичайній ESP32-платі з 4 МБ просто не вистачає флеш-резерву для OTA-
розділу поруч із прошивкою, вебпорталом і вашою конфігурацією.

## Стандартна збірка: оновлення через serial

У стандартній схемі з одним застосунком оновлення — це [перепрошивання через
USB](/gekko/getting-started/flashing/). Конфігурація пристрою зберігається в
NVS і переживає перепрошивання — але все одно варто мати
[резервний bundle](/gekko/guides/backup-restore/) перед оновленням.

## PlatformIO OTA upload (для розробників)

Для плат із достатньою кількістю флешу та OTA-розміткою середовище
`esp32dev_ota` у PlatformIO доставляє той самий образ по мережі замість
serial:

```sh
pio run -e esp32dev_ota -t upload
```

Це свідомо лише alias для способу доставки `esp32dev` — той самий образ,
ті самі build flags — щоб serial- і OTA-доставка лишалися байт-ідентичними.

## Web OTA (завантаження через портал)

Прошивка з увімкненою опцією Web OTA додає в портал сторінку **OTA**:
завантажте образ прошивки з браузера, і пристрій перевірить його, завершить
запис та перезавантажиться в нього. Занадто великі або перервані завантаження
не чіпають працюючу прошивку. На збірках без цієї функції портал просто
ховає сторінку OTA.

:::note
Розглядайте Web OTA як development/advanced-функцію: вмикайте її лише на
платах із запасом флешу, згідно з `docs/platformio-environments.md` у
репозиторії.
:::
