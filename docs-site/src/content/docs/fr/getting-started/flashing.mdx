Les binaires prêts à flasher (`bootloader.bin`, `partitions.bin`,
`firmware.bin`, `littlefs.bin`) sont produits à chaque commit pour chaque puce
prise en charge (ESP32 classique, ESP32-S2, ESP32-S3, ESP32-C3, ESP32-C6) et
incluent à la fois le firmware et les ressources du portail web.

## Choisir une variante du firmware

| Variante | Configuration WiFi par BLE | GPIO 32 | Point d'accès et portail web | Puces |
| --- | --- | --- | --- | --- |
| **Recommandée** | Le code BLE n'est pas compilé | Disponible pour un autre périphérique | Disponibles | ESP32, S2, S3, C3, C6 |
| **Avec BLE** | Incluse | Réservé au bouton d'activation BLE | Disponibles | ESP32, S3, C3 uniquement |

Choisissez **Recommandée** sauf si vous devez configurer le WiFi depuis une
application BLE mobile : ce firmware est plus compact et ne réserve pas
GPIO 32. Choisissez **Avec BLE** uniquement si cette configuration par
application vous est nécessaire ; elle n'existe pas pour l'ESP32-S2 (pas de
radio BLE) ni l'ESP32-C6 (un conflit de l'éditeur de liens dans le framework
`pioarduino`/Arduino-ESP32 core 3.x) — voir `docs/esp32-board-models.md` dans
le dépôt.

## Option 1 — Installateur web (le plus simple)

Flashez directement depuis le navigateur, sans logiciel à installer :

<LinkButton href="/gekko/install/" icon="rocket">Ouvrir l'installateur web Gekko</LinkButton>

<Steps>

1. Connectez votre carte à votre ordinateur avec un câble USB **de
   données**.

2. Ouvrez l'installateur dans **Chrome**, **Edge** ou **Opera** sur ordinateur
   (Web Serial n'est pas disponible dans Firefox/Safari ni sur mobile).

3. Choisissez **Recommandée** ou **Avec BLE**, cliquez sur son bouton
   d'installation, sélectionnez le port série, puis confirmez. L'installateur
   détecte automatiquement la puce connectée — inutile de la choisir
   vous-même.

4. Attendez la fin de la barre de progression, puis continuez avec
   [Premier démarrage et configuration WiFi](/gekko/fr/getting-started/first-boot-wifi/).

</Steps>

:::caution
Le flashage depuis le navigateur dépend du support série de l'OS et de la
puce USB, et présente des problèmes connus sur certaines combinaisons Linux +
puce USB-série. En cas d'échec, utilisez l'une des options ci-dessous —
elles flashent exactement les mêmes binaires.
:::

## Option 2 — esptool

<Tabs syncKey="os">
  <TabItem label="Windows / macOS / Linux (sans Python)">

    1. Téléchargez le binaire autonome `esptool` pour votre OS depuis la
       [page des versions d'esptool](https://github.com/espressif/esptool/releases).
    2. Placez-le à côté des scripts dans le dossier `webflash/` du dépôt
       (renommez-le en `esptool` sur macOS/Linux, `esptool.exe` sur Windows).
    3. Exécutez le script de flashage, en faisant correspondre `CHIP` à votre
       carte (`esp32` par défaut, `esp32s2`, `esp32s3`, `esp32c3`, `esp32c6`).
       Sans argument de port, esptool le détecte automatiquement.

       ```sh
       webflash/flash.sh [default|ble] [CHIP] [PORT]   # macOS/Linux
       webflash/flash.bat [default|ble] [CHIP] [PORT]  # Windows
       ```

       Exemple — une build BLE pour une carte ESP32-C3 :

       ```sh
       webflash/flash.sh ble esp32c3
       ```

  </TabItem>
  <TabItem label="Python">

    ```sh
    pip install esptool
    python3 webflash/flash.py [default|ble] [CHIP] [PORT]
    ```

  </TabItem>
</Tabs>

## Option 3 — PlatformIO (pour le développement)

Si vous compilez depuis les sources :

```sh
# Recommandée (sans BLE)
pio run -e esp32dev -t upload
pio run -e esp32dev -t uploadfs

# Avec BLE
pio run -e esp32dev_ble -t upload
pio run -e esp32dev_ble -t uploadfs

# Autres puces : esp32s3[_ble], esp32c3[_ble], esp32s2, esp32c6
pio run -e esp32s3_ble -t upload
```

Voir `CLAUDE.md` et `docs/platformio-environments.md` dans le dépôt pour le
flux de développement complet.
